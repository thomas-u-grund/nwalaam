# GOTCHA - known pitfalls of nwalaam

- **ALAAMEE's pooled standard error is not used.** ALAAMEE (R script `computeALAMEEcovariance.R`) combines the runs by inverse-variance weighting, so its pooled standard error is the single-run one divided by sqrt(runs): it shrinks with the number of runs although the information part does not. Against the exact maximum likelihood of a 16-node network (`cscripts/test_nwalaam_exact.do`, all 2^16 outcome vectors) the single-run standard error is right (ratio 1.00) and the pooled one was 0.15 of the truth with 40 runs. nwalaam averages the information part over the runs and divides only the Monte-Carlo part by the number of runs. Its covariance is inv(batch-means covariance of dzA) + Monte-Carlo variance; the literal ALAAMEE formula solve(cov/N) was not used (it gave standard errors 22 times too large with N = 490).
- **The pseudo-likelihood estimate may not exist** (perfect separation): the karate club with density, activity and contagion is separated. `mple` then stops with r(430); a normal EE fit shows the missing value in `e(b_mple)`.
- **Tiny networks are badly identified**: with 12 to 16 nodes the exact standard errors are large and collinearity (density, activity, two-star) is strong; use such networks only for the exact test.
- **Mata `tokens(s, "()")` treats the two characters as a binding pair**, not as two parse characters; `alaam_effects()` pads the parentheses with blanks instead.
- **Mata one-line `if (...) if (...) {` and `{ a; break }` are syntax errors.** Write the blocks out.
- **Mata classes cannot be declared from the interactive prompt** (`class AlaamNat scalar N` fails): tests use `AlaamChangeStats()`.
- **The directed 3-cycle statistics count every cycle once per node**: the definition used in `dev/gen_ref_definitions.py` counts each cycle with its smallest node first; an early version counted three rotations and disagreed by exactly that factor.
- **ALAAMEE source could not be run here**: the tests compare with the definitions, not with the Python code (the sandbox refused to execute the downloaded repository).
- **The EE update of ALAAMEE is biased against the exact maximum likelihood estimate**, and it is not a learning-rate effect (dev/ee_bias.do, karate club, exact 0.535 / -0.832 / 1.461; EE with lrate 0.05: -0.01 / -0.53 / 1.07, 0.01: -0.03 / -0.75 / 1.53, 0.002: -0.07 / -0.86 / 1.77): Density stays near 0 for every rate and the other two coefficients slide along the nearly collinear direction of the statistics. The karate outcome has a two-mode distribution (almost all or almost none of the actors with the outcome): the stationary mean statistics at the EE estimate are far from the observed ones (`estat gof` shows it). The default is therefore stochastic approximation; `method(ee)` is kept to reproduce ALAAMEE.
- **Stochastic approximation needs a damped derivative matrix.** From the Algorithm S start the covariance of the simulated statistics can be that of a single state (the chain does not move), and the full Newton step diverges (theta of 500 and more). The plugin shrinks the off-diagonal elements by 30 percent, floors the variances and caps the largest change of a coefficient at 0.25 per iteration.
- **Mata `tbl = (a \ b \ ... )` with more than about 50 string elements stops with "too many tokens"**: build long tables in chunks (`tbl = tbl \ (...)`).
- **A running Stata that has loaded the plugin is killed by macOS when the plugin file is rebuilt in place**: `rm` the plugin before copying; the Makefile writes through `lipo`, so do not rebuild while a test runs.
- **Algorithm S start (fixed in 1.4.0)**: plugin code 12 (`native/alaam_sim.c`) capped the step at +0.1 only, so a nearly zero statistic of a centred covariate gave -3e25 (seed 111 of the glasgow smoking model) and starts of 400 to 1800 for other seeds. Since 1.4.0 the step is capped at -0.1 as well (ALAAMEE's `initialEstimator.py` caps only upwards: deliberate difference, in CHANGELOG and help). All SA estimates for a given seed changed slightly then. The 1.3.1 staged restart in `AlaamSA()` stays as a second line of defence (not reached for seeds 1-30 and 111).
- **A missing covariate value was counted as 0** until 1.3.1; `_nwalaam_prep` now stops with r(416). The change-statistic tests against ALAAMEE still use missing values (Mata level, not through the command).

## Threads in the plugin (1.1.0)
The independent EE runs (`method(ee)`, plugin code 22) run in threads (pthreads on macOS and Linux, `_beginthreadex` on Windows). Rules that keep it correct:
- No Stata plugin interface call (`SF_*`) from a worker thread: workers only fill their own part of a buffer, and the calling thread writes the buffer to the frame variable after all threads have finished.
- Every run has its own generator (seed + 1000003 x run number) and its own scratch memory (`Model.cnt` is copied per run), so the result is the same for every number of threads (`test_nwalaam_threads.do`). New state that the samplers write to must be per run, never global (the old global `cur_rng` was removed for this reason).
- The Linux build needs `-pthread` (Makefile); the Windows build (`cl /LD`, multithreaded CRT by default) needs nothing extra. SA, `simulate` and `estat gof` follow one chain each and stay single-threaded, because splitting a chain would change the results; the book examples print numbers from them.

## Plots

- A `syntax` option `P(integer)` is the local `p`, not `P`: `matrix[`i', `P' + `k']` read column `k` of the trace matrix (the coefficient columns, missing after `method(sa)`), so the dzA panels of `estat mcmcdiag, plot` were empty or repeated the coefficient trace until 1.2.x; use the lower-case name in the program that receives the option.
- The plots call the core helper `_nw_gfinish` (core 3.29.0): `check` first, `title ..., noblack` for the two plots of 1.2.0 (their default title is the plain scheme title; black titles would change the released pictures), `save` last. The helper is called after `graph combine`, never after a `nodraw` panel. `nwalaam_plots_defaults.do` and `test_nwalaam_plots.do` compare the default PNG with the released package (set `NWALAAM_PLOT_REF`; produce the reference after `cscript`: the rendering state changes the PNG bytes). The released 1.2.0 draws the graph only under the name `Graph`: export it without `name()` in the reference script.
- No local fallback when the core is too old: `_nwalaam_corecheck` stops with r(199) at plot time. No dialog: the package has none and none is added.
